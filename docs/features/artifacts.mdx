Agents leave a paper trail: a plan before the work, an RFC to argue a decision, a spec to pin down behaviour, a note explaining the result. The **Artifacts** tab is a store of that trail. Every markdown document an agent writes is captured as it is written and kept under Claude Board's own directory, so the trail survives even when the branch it was written on does not.

## Opening the Artifacts tab

Open any project, then click the **Artifacts** tab in the top view tabs — the same row that holds Board, Roadmap, and Terminal.

The tab is a two-pane browser: the document list on the left, the selected document on the right.

## What gets captured

Claude Board records every tool call an agent makes, including the file each `Write`, `Edit`, `MultiEdit` and `NotebookEdit` touched. When one of those writes a `.md` or `.mdx` file inside the project, the document is copied into the store when the task completes.

That means the store holds what agents actually produced. Files you wrote by hand, vendored documentation, and the repository's own `README.md` are not artifacts and do not appear.

| Rule | Behaviour |
|------|-----------|
| Extensions | `.md` and `.mdx` only |
| Location | Inside the project's working directory. A document written to a temp directory or elsewhere outside the project is not captured |
| Identity | One artifact per source document. A document edited by three tasks is one artifact, not three |
| Timing | Captured when the task completes, before its worktree is removed |

Agents run in a per-task git worktree that is deleted once the task finishes, so a document is copied out before that happens. This is why an artifact outlives the task, the branch and the worktree that produced it.

### Where documents are stored

Under Claude Board's data directory, beside the database rather than inside it — `~/.claudeboard/artifacts` for a data directory of `~/.claudeboard/data`. Filenames are readable: a kebab-case version of the document's own name plus the Unix second it was first captured.

```
~/.claudeboard/artifacts/auth-plan-1754400000.md
```

A readable path matters because artifacts are meant to be referenced. An agent handed that path can read the document itself, which keeps prompts small and means a reference still resolves after the document is edited. A document keeps its filename for its whole life for the same reason.

### What each row shows

- **Title** — the document's first H1, or the `title:` key from its YAML front matter when there is no H1, or its filename
- **Preview** — the opening body text as plain prose, with front matter, fenced code blocks, and markdown syntax stripped out
- **Kind** — a badge derived from the document's original path
- **Size** and **updated time** — `12.4 KB`, `5m ago`, `2d ago`, or a date once the document is more than a week old

### Kinds

The **kind** badge is inferred from the source path, checked from the most specific match to the least:

| Kind | Matches |
|------|---------|
| Readme | A file named `README.md` or `README.mdx` |
| Plans | `plan` anywhere in the path |
| RFCs | `rfc` anywhere in the path |
| Specs | `spec` or `design` anywhere in the path |
| Docs | A `docs` directory anywhere in the path |
| Other | Everything else |

Filter the list to a single kind with the kind tabs, and narrow it further with the search box — search matches on name, source path, and title.

## Tracing a document back to its task

Each artifact records the task that first created it and the task that most recently wrote it. Click through to open that task and read the prompt, the log, and the diff behind the document.

Deleting a task does not delete the documents it produced. The attribution clears; the artifact stays.

## Working with a document

<Steps>
  <Step title="Preview" icon="eye">
    Select a row to render the document as formatted markdown in the right pane.
  </Step>
  <Step title="Edit and save" icon="pen">
    Click **Edit** to switch the pane to a plain-text editor. **Save** rewrites the stored copy; an **Unsaved changes** marker tracks edits you have not committed yet.
  </Step>
  <Step title="Reveal in file manager" icon="folder-open">
    Open the store directory in Finder, File Explorer, or your Linux file manager, with the document selected.
  </Step>
  <Step title="Copy path" icon="clipboard">
    Copy the document's absolute path — the form to hand an agent so it can read the document itself.
  </Step>
  <Step title="Delete" icon="trash">
    Remove the document from the store.
  </Step>
</Steps>

<Warning>
  Editing and deleting affect the store only. The file the agent originally wrote is still in your repository, under version control, and is left untouched. Deleting an artifact never deletes your work — but equally, editing an artifact does not change the file in your repo.
</Warning>

## Desktop app only

The Artifacts tab reads and writes files on the machine running Claude Board, which the browser cannot do. It is available in the desktop app; in the browser, the tab reports that artifacts require the desktop app.

<Tip>Point your agents at a convention — plans under `plans/`, decisions under `docs/rfcs/` — and the kind badges turn the Artifacts tab into a table of contents for the project's thinking.</Tip>
