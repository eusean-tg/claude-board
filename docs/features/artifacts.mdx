Agents leave a paper trail: a plan before the work, an RFC to argue a decision, a spec to pin down behaviour, a note explaining the result. The **Artifacts** tab is a store of that trail. An agent saves a document to it deliberately, and it is kept under Claude Board's own directory — so the trail survives even when the branch the work was done on does not.

## Opening the Artifacts tab

Open any project, then click the **Artifacts** tab in the top view tabs — the same row that holds Board, Roadmap, and Terminal.

The tab is a two-pane browser: the document list on the left, the selected document on the right.

## What gets saved

An agent saves a document by calling the **save_artifact** tool with a title, a kind, tags and the content. Nothing is inferred: the document is an artifact because the agent decided it was one, and its title is the title the agent gave it.

That means the store holds what agents meant to record. Files that belong to the codebase — source, configuration, docs-site pages, a README — are written to the repository as normal and never appear here.

| Given by the agent | Derived |
|---|---|
| Title, kind, tags | Preview, size, filename |

The prompt for every task explains this, so an agent producing a plan or a set of research notes saves it without being asked.

### Where documents are stored

Under Claude Board's data directory, beside the database rather than inside it — `~/.claudeboard/artifacts` for a data directory of `~/.claudeboard/data`. Filenames come from the title plus the Unix second it was saved.

```
~/.claudeboard/artifacts/auth-rollout-plan-1754400000.md
```

A readable path matters because artifacts are meant to be referenced. An agent handed that path can read the document itself, which keeps prompts small and means a reference still resolves after the document is edited. A document keeps its filename for its whole life for the same reason.

### Referencing a document from a task

Open a task, go to **Documents**, and pick the documents it should read. Referenced documents are listed in that task's prompt by absolute path, with instructions to read and update them there.

For documents every task should know about, set a **Shared Document Tag** in project settings — `context`, say — and tag the documents that qualify. They are named in every task's prompt for that project. Leave it empty to share none.

Beyond the handful listed inline, an agent can call **list_artifacts** to see the rest, optionally filtered by tag.

### What each row shows

- **Title** — the title the agent or you gave it
- **Preview** — the opening body text as plain prose, with front matter, fenced code blocks, and markdown syntax stripped out
- **Kind** — plan, RFC, spec, readme, doc or other, as classified when saved
- **Size** and **updated time** — `12.4 KB`, `5m ago`, `2d ago`, or a date once the document is more than a week old

### Filtering

Filter to a single kind with the kind tabs, to a single tag with the tag chips, and narrow further with the search box.

Tags work the same way task tags do. Edit them in the detail pane; an agent can also set them when it saves a document, which is what makes the shared-tag setting useful without tagging anything by hand.

## Tracing a document back to its task

Each artifact records the task that first created it and the task that most recently wrote it. Click through to open that task and read the prompt, the log, and the diff behind the document.

Deleting a task does not delete the documents it produced. The attribution clears; the artifact stays.

## Working with a document

<Steps>
  <Step title="Preview" icon="eye">
    Select a row to render the document as formatted markdown in the right pane.
  </Step>
  <Step title="Edit and save" icon="pen">
    Click **Edit** to switch the pane to a plain-text editor. **Save** rewrites the stored copy; an **Unsaved changes** marker tracks edits you have not committed yet.
  </Step>
  <Step title="Reveal in file manager" icon="folder-open">
    Open the store directory in Finder, File Explorer, or your Linux file manager, with the document selected.
  </Step>
  <Step title="Copy path" icon="clipboard">
    Copy the document's absolute path — the form to hand an agent so it can read the document itself.
  </Step>
  <Step title="Delete" icon="trash">
    Remove the document from the store.
  </Step>
</Steps>

<Warning>
  The store is the only copy of an artifact. Deleting one deletes the document — there is no repository copy to fall back on, because a saved artifact was never written into the repository in the first place.
</Warning>

## Desktop app only

The Artifacts tab reads and writes files on the machine running Claude Board, which the browser cannot do. It is available in the desktop app; in the browser, the tab reports that artifacts require the desktop app.

<Tip>Set a shared tag like `context` and have your agents tag the documents that describe how the project works. Every later task is then told about them without you doing anything, which turns the Artifacts tab into the project's working memory.</Tip>
