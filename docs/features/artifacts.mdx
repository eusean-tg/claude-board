Agents leave a paper trail: a plan before the work, an RFC to argue a decision, a spec to pin down behaviour, a README to explain the result. The **Artifacts** tab collects every markdown file in the project's working directory into one browsable list, so that trail is readable without leaving the board or digging through directories.

## Opening the Artifacts tab

Open any project, then click the **Artifacts** tab in the top view tabs — the same row that holds Board, Roadmap, and Terminal.

The tab is a two-pane browser: the file list on the left, the selected file on the right.

## How files are discovered

Each time the tab loads, Claude Board walks the project's working directory and collects the markdown it finds:

| Rule | Behaviour |
|------|-----------|
| Extensions | `.md` and `.mdx` only |
| `.gitignore` | Patterns in the working directory's `.gitignore` are honoured — ignored files stay out of the list |
| Excluded directories | `node_modules`, `.git`, `dist`, `build`, `.next`, `target`, `__pycache__`, `.venv`, `vendor`, and `.cache` are skipped regardless of `.gitignore` |
| Depth | The walk descends at most 12 directory levels |
| File size | Files larger than 1 MB (1,048,576 bytes) are skipped |
| List size | The list holds up to 1,000 files, most recently modified first |

Symlinked directories are not followed, so a link pointing back up the tree cannot produce duplicate or out-of-project entries.

### What each row shows

- **Title** — the file's first H1, or the `title:` key from its YAML front matter when there is no H1, or the filename
- **Preview** — the opening body text as plain prose, with front matter, fenced code blocks, and markdown syntax stripped out
- **Kind** — a badge derived from the file's path
- **Size** and **modified time** — `12.4 KB`, `5m ago`, `2d ago`, or a date once the file is more than a week old

Rows are grouped by directory, with files at the working directory root first and the remaining directories in alphabetical order.

### Kinds

The **kind** badge is inferred from the path, checked from the most specific match to the least:

| Kind | Matches |
|------|---------|
| Readme | A file named `README.md` or `README.mdx` |
| Plans | `plan` anywhere in the path |
| RFCs | `rfc` anywhere in the path |
| Specs | `spec` or `design` anywhere in the path |
| Docs | A `docs` directory anywhere in the path |
| Other | Everything else |

Filter the list to a single kind with the kind tabs, and narrow it further with the search box — search matches on filename, relative path, and title.

## Tracing a file back to the task that wrote it

Claude Board records every tool call an agent makes, including the file each `Write` and `Edit` touched. An artifact is linked to a task by matching its path against those recorded calls, so a file carries a **Created by** line naming the tasks that wrote it. Click through to open that task and read the prompt, the log, and the diff behind the file.

Files you wrote by hand, or that predate the board, simply have no linked task.

## Working with a file

<Steps>
  <Step title="Preview" icon="eye">
    Select a row to render the file as formatted markdown in the right pane.
  </Step>
  <Step title="Edit and save" icon="pen">
    Click **Edit** to switch the pane to a plain-text editor. **Save** writes the file back in place; an **Unsaved changes** marker tracks edits you have not committed yet.
  </Step>
  <Step title="Reveal in file manager" icon="folder-open">
    Open the file's directory in Finder, File Explorer, or your Linux file manager, with the file selected.
  </Step>
  <Step title="Copy path" icon="clipboard">
    Copy the file's path relative to the working directory — the form to paste into a task description or a prompt.
  </Step>
  <Step title="Jump to the authoring task" icon="arrow-right">
    Open the task whose `Write` or `Edit` call produced the file.
  </Step>
</Steps>

Saving overwrites a file that already exists; the Artifacts tab does not create new files. Ask an agent to write the file, or create it yourself, and it appears in the list on the next refresh.

<Info>
  Editing is confined to markdown files inside the project's working directory. Absolute paths, and paths that climb out of the working directory with `..` or through a symlink, are refused.
</Info>

## Desktop app only

The Artifacts tab reads and writes files on the machine running Claude Board, which the browser cannot do. It is available in the desktop app; in the browser, the tab reports that artifacts require the desktop app.

<Tip>Point your agents at a convention — plans under `plans/`, decisions under `docs/rfcs/` — and the kind badges and directory grouping turn the Artifacts tab into a table of contents for the project's thinking.</Tip>
